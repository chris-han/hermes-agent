## 第 2 页｜同一材料，比较两种问法
时段：9:15-9:40。**使用工具：豆包或 DeepSeek，任选一个。** A／B 两轮保持同一平台、同一模型、同一会话与同一组模拟文件。此练习不使用 Semantier 的 Resume Screening 入口；后续学生记录与财务练习再使用课堂 Semantier 环境。只上传本包虚构简历与 JD，不上传真实个人或学校内部资料。

### 步骤 03｜上传简历与 JD，运行模糊 Prompt
使用文件：resume-sample-zh.pdf + jd-sample-zh.pdf。
操作：在豆包或 DeepSeek 新建会话，使用可用的附件入口添加这两份模拟文件。若当前模式无法读取附件，从 PDF 中复制正文，并保留文件名。两轮使用相同输入方式；随后发送下面的 Prompt，保留输出为 A。
```text
帮我看看这份简历。
```
检查：回答是否说清评估目的？有没有逐项引用？有哪些结论无法核对？不要预设模糊 Prompt 一定差，按实际输出记录。

### 步骤 04｜同一会话运行结构化 Prompt
使用文件：继续使用步骤 03 的两份附件，无需重复上传。
操作：复制以下完整 Prompt，保留输出为 B；对照 A 找出三处具体差异。
```text
请仅依据当前会话中的 resume-sample-zh.pdf 和 jd-sample-zh.pdf，
完成一次教学用的岗位要求与简历证据对照，不做录用决定。

1. 从 JD 提取岗位要求，区分必需条件和优先条件。
2. 对每项要求，给出：有直接证据／部分有证据／材料未提供／存在矛盾。
3. 输出表格：岗位要求｜JD 原文｜简历原文｜判断｜仍需核实的问题。
4. 引用必须来自这两份附件。能定位时写文件名、PDF 页码与原文片段；
   无法取得页码时明确写“页码未取得”，不得编造。
5. 材料未提供的内容写“未提供”，不根据年龄、婚育、健康等推断能力。
6. 最后用不超过 100 字说明当前材料能够支持什么、不能支持什么。
```
完成标志：找到至少一项能对上原文的结论和一项证据不足；记录 A、B 在目标清晰度、依据、遗漏或可验收性上的三处差异。

### HR 练习到此结束
HR 只完成步骤 03、04：保持模型、简历、JD 和评估目的相同，比较模糊 Prompt 与结构化 Prompt 的 A／B 输出。记录三处差异及其输出位置，并说明目标、证据要求和输出格式如何影响结果；不再增加第三轮重跑、JD 脱敏或用途切换任务。Prompt 更清楚不保证答案正确，仍需抽查原文。

## 第 3 页｜学生记录：同一文件，两种用途
时段：10:20-10:35。本节专门演示“同一文件、两种用途”：模型和文件保持不变，只把用途从校内协调切换为第三方共享，比较保护建议如何变化。仅使用模拟学生样本，不上传真实完整医疗、心理或纪律档案。

### 步骤 05｜生成校内使用候选版
使用文件：student-records-sample-zh.pdf。
操作：进入对应课堂会话，上传该 PDF，检查解析完成后发送：
```text
请仅依据附件 student-records-sample-zh.pdf，为“校内学生支持协调”
制作教学用信息保护建议与候选版本。
先列出信息字段、原文证据、PDF 页码（取不到写未取得）、
本用途必要性和建议保护动作，再生成最小必要的候选版本。
区分个人身份、学业、家庭与健康等信息；不得推断未提供的情况。
哪些内容应由学校制度决定，请单独列为待确认。
```
检查：是否保留了协调工作必需的信息？不确定事项是否清楚列出？

### 步骤 06｜切换第三方用途并检查组合风险
使用文件：同一份 student-records-sample-zh.pdf；继续同一会话，保持模型与文件不变，只改变使用目的，无需重复上传。
```text
仍使用同一附件，现在将用途改为“向第三方分享学生支持案例”。
请重新给出保护建议与候选版本，并与校内版逐项比较变化及理由。
删除姓名后，再检查班级、活动、家庭背景、健康和其他稀有特征
能否组合造成重识别风险。给出至少一条有原文支持的可能路径；
这只是风险分析，不要声称已经识别真实个人。
为每条发现提供文件名、可取得的 PDF 页码与原文片段，
没有原文依据的内容不补造；不发送给任何第三方。
```
操作：选择一条标注，点击实际存在的来源引用并核对原文；没有引用入口则手动核对，并记“自动定位未验证”。
完成标志：记下一处两版本差异、一条组合风险和一个制度待确认问题。本练习不安排权限账号、审批角色或限时查看操作。

### 步骤 07｜上传发票，核对票面事实
使用文件：北京象鲜科技有限公司_发票金额45.92元.pdf。
操作：打开讲师部署的“报销政策审阅”（/ontology-workbench2?taskIntent=expense-reimbursement），上传发票。先将申请人、部门和用途留空，运行界面支持的检查，再核对票面字段与来源。使用聊天补充说明时，可参考：
```text
请读取本会话上传的发票 PDF，提取开票日期、购销方、
票面金额、税额及可取得的其他必要字段。
逐项输出：字段｜实际值或未知｜原文片段｜PDF 页码或未取得。
金额和日期必须依据票面，不从文件名推断。
请如实说明实际采用的是文本抽取还是 OCR／视觉识别；
若无法知道处理方式，写“处理方式未取得”。
暂不判断是否能报销，不补齐票面未提供的信息。
```
检查：用原始 PDF 核对至少金额和日期两项。文件名中的 45.92 元不是验证依据。

### 步骤 08｜打开本次教学政策
使用文件：继续使用发票；另需讲师提供并接入的 财务报销政策.pdf。
操作：打开应用中实际绑定的政策与来源版本，对照发放的教学政策 PDF。仅上传政策文件不等于完成政策建模或绑定；未取得适用政策时，停止政策判断并记录缺失。
```text
请列出本次报销检查实际使用的政策文件、可取得的版本或来源标识，
以及与当前发票相关的条款原文和 PDF 页码。
区分政策条件、票面事实与仍缺少的申请信息。
若政策未加载、版本未取得或条款无法定位，请明确说明；
不得使用模型记忆代替本次教学政策，也不复制虚构条款。
```
完成标志：你能打开所用政策，并核对一条实际条款；没拿到政策依据时，记录“政策检查未运行”。

## 第 5 页｜发票：检查建议，沿来源回到原文
时段：继续 10:35-11:00。检查建议不等于审批，上午不执行提交、批准、付款或过账。

### 步骤 09｜取得建议并核对双端来源
使用文件：步骤 07 的发票 + 步骤 08 的实际教学政策。
```text
请读取当前报销检查结果，核对实际绑定的发票、教学政策
和界面显示的演示提交日期；本练习默认日期为 2026-10-15。
输出：票面事实；实际适用条款；检查建议；缺失信息；例外条件。
将用户补充、政策判断和模型推测分别标记，不混为票面事实。
每条关键建议分别关联政策原文和发票原文，提供真实可用的来源入口；
页码或定位不可取得时明确说明，不编造链接。
只检查，不提交报销、不审批、不付款。
```
操作：选一条关键建议，分别打开政策来源与发票来源，核对文件、页面、片段和高亮是否真的支持建议；若页面已接入政策图谱与全局 Inspector，再沿同一建议查看适用条款及条件。若结果包含模型推测，检查它是否单独标为推测并关联实际支持材料；无依据时保留未知，不能把推测当作票面事实或政策规定。
检查：解释文字不等于 lineage。自动定位失败时记录实际状态；手动打开原件只证明你进行了人工核对。

### 步骤 10｜只改一个支持的输入后重跑
使用文件：仍是同一张发票与同一版本政策；不要改变票面事实。
操作：在界面填写虚构申请人、部门与教学用途，只更改一项真实支持的输入后重跑。不要为了制造变化而改票面日期或教学政策。缺失字段减少不等于获得批准，也不会自动消除超期例外。
```text
请读取本次重新检查后的实际结果，与上一次比较：
哪些输入发生变化，哪些缺失信息已补齐，
哪些政策条件和例外仍然存在？分别引用当前结果与政策依据。
用户填写的用途属于用户补充，不是从发票识别出的事实。
本操作不提交报销、不审批、不付款。
```
如果应用不支持所选字段，记录“该输入不可修改”，不把聊天中声称已改当成重跑成功。
完成标志：记录变更输入、两次实际字段值、建议变化或不变及依据。11:00 到点即进入下一节。

使用条件：先由讲师确认“标注结果链接、原文高亮、规则图谱”已接通并通过本次部署验收。未接通时记录“本链路未运行”，可人工阅读样本；人工核对不算自动回溯通过。

1. 从 /workshop 领取指定 PDF，进入 Chat 新建会话，通过上传按钮添加文件；确认上传完成，不只发送文件路径。
2. 复制下列 Prompt 并发送。返回结果应明确标示“模拟数据／教学示例规则／预置标注”，并提供真实可点击的“查看敏感信息标注”链接。

### 点击后按此顺序检查
3. 点击“查看敏感信息标注”，确认 Flyfish 打开的是刚上传的原始 PDF，且能看到标注高亮。
4. 选择一处高亮，阅读信息类别、敏感原因、保护建议和关联教学规则；查看规则的适用条件及限制。
5. 打开该标注关联的规则图谱，找到“标注—教学规则—原文证据”的关系；点击原文证据，确认回到同一 PDF 的正确页与片段，而不只是显示解释文字。
6. 再选另一类标注，重复步骤 4–5。可选采购报价、未审定现金流预测、扩校计划或欠费组合线索，以页面实际提供的标注为准，不要求自行补全全部风险。
7. 返回 Chat 后重新打开结果，核对仍是同一材料、结果及所选标注。不能打开、无高亮或指向错误位置时，记录实际失败步骤。

### 完成记录与教学边界
在笔记中为两条标注分别记录：原文及页码、对应规则、敏感原因、保护建议，以及图谱到原文的跳转是否成功。再写一个规则适用限制或待学校确认的问题。

本演示针对固定 PDF 预置少量规则与标注，不证明其他财报的自动识别能力。原文证明“材料写了什么”，教学规则解释“在这个用途下为什么建议保护”；两者不等于正式制度或法律认定。结果链接不代表已永久修改原 PDF。

与学生记录练习的分工：学生场景比较“用途变化如何改变保护建议”；本页检查“为什么标注、规则是什么、证据在哪里”。与发票场景的分工：发票检查实际政策条件，本页展示教学敏感规则的解释与回溯。

### 步骤 13｜整理并检查自己的成果

11:15-11:25：在自己的笔记中整理 A／B 差异、一个成功发现、一个疑点及其来源。保留 Prompt 与结果；仅在获准位置保存或导出。
11:25-11:45：参加跨组展示或写书面点评。问“依据能否核对、是否漏报／误报、保护后还能否用”，而不只评价表达。
11:45-11:55：提交一条目录或规则缺口，标明“已有证据支持”还是“仍需核查”。
11:55-12:00：确认作业交付方式与修订机会。课后作业填写八项：任务目的与使用对象、文件类型、发现清单、分类与保护建议、人工纠正版本、受控共享版本、待学校确认事项、依赖的 AI 应用部件。
